# 墨阁 · 本地长篇小说创作 Agent

[![CI](https://github.com/c0py1st/InkSpire/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/c0py1st/InkSpire/actions/workflows/ci.yml?query=branch%3Amain)

一个完全跑在本机的写作工具：**你给一段提示词，它整理出大纲并严格按照大纲写正文**。
所有数据都是磁盘上的普通文件（Markdown + JSON），随时可以用其他编辑器打开，也方便进版本管理。

## 特性

- **开书向导**：一段构想 → 故事内核 → 分卷大纲 → 逐章 beat → 设定集，每一步可重掷、可手改，确认后才落盘。
- **大纲即契约**：写第 N 章时自动注入该章 beat、相邻章走向、出场人物卡、全书文风约定、全部前情摘要与上一章结尾，agent 不许偏离剧情。
- **记忆闭环**：每章「完成」后自动写摘要进记忆，并探测新人物/新设定与已建档人物的状态变化（受伤、立场转变、关键物品得失），全部以待确认建议卡呈现，不静默改你的设定集。采纳的状态变更会按时点记入人物卡的「状态时间线」：重写旧章时注入的是该章当时的状态，后文才发生的变化绝不泄漏；问"第三章时他的伤好了吗"，agent 读卡即可按时间线作答。
- **分层长程记忆**：整卷归档后自动压成一条「卷回本」，续写后续卷时用粗粒度回本顶替整卷逐章摘要、当前卷仍保留细摘要——长篇写到大后期，开篇的人物处境与未决伏笔也不会被上下文预算挤掉。章摘要一旦改动，回本按指纹自动失效回落，绝不拿过期回本当事实。
- **批注抽屉**：边写边问；选中正文任意片段可让 agent 出「润色/扩写/缩写/换个写法」方案，校对式 diff 预览，采纳才生效；不满意可「按反馈再改」，让 agent 基于上一版定向修改而不是推倒重掷。
- **对话式 Agent（ReAct）**：向编辑提问时它会自己决定查什么——搜前文、读人物卡、翻伏笔登记表、读任意章原文，回答附工具调用轨迹；涉及改整章正文/重写摘要一律走提案卡，你点采纳才落盘。对话记录（含未处理的提案卡）按书持久化到 `chat.json`，关掉重开接着聊。
- **前文检索**：左栏一键搜索全书正文——某句话、某个伏笔、某个人物第一次出场在哪，点命中行直接跳进章节并选中该词。内置 SQLite 全文索引（Node 自带模块，零依赖），文件永远是真相源、索引可随手重建；旧版 Node 自动退回全文件扫描，行为一致。
- **一致性检查**：一键核对正文与设定集、前情的时间线与性格矛盾；每条问题的原文引证逐字比对正文，模型编造引证会被标记降权——不拿假证据驱动改稿。
- **世界事件时间线**：跨人物的"世界大事账本"（`events.json`）：归档时自动提取"十几章后仍然要紧"的事件（结盟、死亡、结案、启程），作者可补记可纠错；agent 有 `read_timeline` 工具可按人物/势力过滤、按章截断，回答"到第 X 章世界发生了什么"。
- **世界书（按需激活）**：把世界观拆成"触发词 → 设定"条目（`lorebook.json`），写章时只注入命中本章语料（章题 / 本章 beat / 出场人物 / 上一章结尾 / 前情摘要）的条目——长设定不再每章占用上下文预算。支持按卷/按章段生效、常驻条、"契约条"豁免预算、优先级争夺注入顺序；每次生成的激活/挤掉情况留痕可查；内置**激活测试器**——选一章即可看到每条"为什么注入/没注入"（同源判定，所见即所得）。对话 agent 也有 `read_lorebook` 工具，问"关于 X 有什么设定"能自己查。没有条目的老书，生成行为与此前逐字节一致。
- **通读模式**：全书正文一键连排成一条阅读流（大行距审读排版），搜索词全书高亮、`Enter`/`Shift+Enter` 逐处跳转计数，章题点击可跳回编辑器改稿；长卷按块懒加载，滚动到哪补到哪。
- **网文连载模式（按书开关）**：开启后每章可标「爽点/章末钩子」——生成时作为硬约束注入并做跨章钩子去重；体检面板追加节奏红线（爽点断档告警/覆盖密度/缺钩子章直达）；另有**读者模拟评审**（三类目标读者给本章打分，抱怨必带验真引证）与**黄金三章评审**（开篇当批送审逐章 GO/REVISE/REWRITE）。关闭只是收起编辑入口，已填字段仍随大纲生效。
- **风格范文库（以本书好段落示范笔法）**："读者评审"验真通过的好段落可一键收录进 `exemplars.json`；写章时与世界观同一套触发词引擎按命中注入（独立预算、只模仿笔法句长节奏、严禁抄情节），设定集页可誊录与纠错。没有范文的老书逐字节零影响。
- **伏笔登记表**：埋了什么钩子、计划哪章回收，登记在大纲页；未回收清单随前情摘要注入每章生成，指定本章回收的作为硬性要求，一致性检查同时盯"该收没收"和"提前剧透"。
- **后台生成与可中断**：生成期间可随意切章、切视图，随时「停止生成」，已生成部分自动保留回目标章。
- **挂机连写**：从任意章起按大纲顺序连写 N 章——已有正文的章自动跳过；每章写完自动归档进记忆（下一章即刻读得到）；某章失败则整队停止、已完成的全部保留；结尾被输出上限截断的章自动续写补完一次。关掉浏览器照样跑。
- **字数节奏**：编辑器顶部显示本章目标字数进度（向导里设定），一眼掌握节奏。
- **历史版本**：覆盖重写/大幅删改自动留备份，界面内预览与一键恢复（恢复前再备份一份）。
- **模型自选**：任何 OpenAI 兼容接口都能接（DeepSeek / 硅基流动 / Kimi / OpenRouter / 本地 Ollama），创作与辅助两个槽位可分别配置，模型列表一键拉取。
- **桌面版打包（可选）**：Tauri 外壳 + 随行本地服务，一条 `npm run desktop:build` 产出 Windows 安装器；双击即用不开终端，数据仍是普通文件夹（支持 `MOGE_HOME` 便携模式），关窗零残留。
- **奶油纸质感 UI**：暖纸色底 + 单一黛青强调色，大圆角与柔和阴影，「纸 / 墨 / 跟随系统」三档主题，专注模式隐藏一切干扰；正文字体本地打包，离线也统一。

## 快速开始

### 1. 获取代码

本项目以源码形式分发，没有安装包——克隆仓库即可：

```bash
git clone https://github.com/c0py1st/InkSpire.git
cd InkSpire
```

需要 Node.js ≥ 20（建议 22.5+；依赖的 `fetch`/`node:` 前缀模块与 Vite 6 都要求此版本，全文索引用到 Node 内置 SQLite，22.5 起可用——旧版本自动退回文件扫描，功能不受影响），npm 随装。

### 2. 安装依赖并启动

```bash
npm install
npm run dev
```

然后浏览器打开 http://127.0.0.1:5173 （后端 API 在同机 8787，由前端代理转发，无需单独访问）。

1. 先进「设置」：默认预置了 DeepSeek 官方配置档，把你的 API Key 粘进去，点「测试连接」。
2. 回首页点「开新书」，把你的想法写成一段提示词，跟着向导走完六步。
3. 左栏选一章 → 「生成本章」→ 阅读修改 → 「完成本章」归档记忆。

> 没填 Key 也能玩：应用处于**演示模式**，完整流程可用，只是内容是本地生成的占位文字。

> 你的书稿都在 `data/` 目录里，该目录不入库；换机器时整个文件夹拷走即可。

## 生产模式（可选）

```bash
npm run build   # 构建前端到 web/dist
npm start       # 仅启动后端，同时托管前端静态文件，访问 http://127.0.0.1:8787
```

日常写作也可以一直用 `npm run dev`，两者功能没有差别。

## 桌面版打包（可选）

想要"双击即用、不开终端"的单机版，可打包成 Windows 桌面应用（Tauri 外壳 + 随行的本地服务）。
`desktop/` 是**独立的 npm 项目**（不挂主仓库 workspaces）——纯 WebUI 使用者 `npm install`
完全碰不到 Rust/Tauri 依赖，打包工具链只装给打包者；二进制发行物走 GitHub Releases，永不进 git。

```bash
npm run desktop:build      # 一步到位：构建前端 → 装 desktop 自己的依赖 → 产出 NSIS 安装器
# 产物：desktop/src-tauri/target/release/bundle/nsis/墨阁_<版本>_x64-setup.exe（约 44MB）
```

安装后从开始菜单启动。数据目录三级策略：**exe 旁边有 `data/` 文件夹即自动便携**（书稿跟着走，
适合 U 盘/多机）；否则默认 `%APPDATA%\app.inkspire.moge\data`；也可用环境变量 `MOGE_HOME=<目录>`
显式指定。运行时与浏览器版功能完全一致：外壳只做"起本地服务 → 等就绪 → 开窗口"，
关窗进程一起退出，不留后台残留。

### 发版流程

```bash
npm run desktop:bump 0.2.0    # 版本一次写齐 4 处（根/desktop 的 package.json、tauri.conf、Cargo.toml）
npm run desktop:build         # 产出安装包（Cargo.lock 随构建自动更新）
git add -A && git commit -m "chore(release): v0.2.0" && git tag v0.2.0
git push && git push origin v0.2.0
gh release create v0.2.0 "desktop/src-tauri/target/release/bundle/nsis/墨阁_0.2.0_x64-setup.exe" -n "墨阁 v0.2.0"
```

> 构建机需要 Rust（GNU 工具链）与 `gh`（scoop 装，落 E 盘）；NSIS 等打包工具缓存在
> `E:\dev-rust\tauri`（junction 供 tauri 寻址），发版构建不需要联网取工具。
> 环境细节与踩坑记录见 `AGENTS.md`。开发调试：`npm run desktop:dev`。

## 数据放在哪

```
data/
  .config.json            # 模型配置与密钥（仅本机）
  <你的书>/
    meta.json             # 书名、简介
    outline.json          # ★ 结构化大纲 = agent 的契约
    bible/characters.json # 人物卡（含 stateHistory 按章状态时间线，采纳状态变更建议时写入）
    bible/worldview.md    # 世界观自由文本
    chapters/v01c001.md   # 每章正文（带 frontmatter）
    summaries.json        # agent 维护的前情摘要
    events.json           # 世界事件时间线（归档自动提取 + 作者补记，真相源）
    lorebook.json         # 世界书条目（触发词→设定，真相源；生成时按命中激活注入）
    exemplars.json        # 风格范文库（评审验真后一键收录；生成时同引擎命中注入）
    chat.json             # 批注抽屉的对话记录（含未决提案卡，刷新不丢）
    recaps.json           # 卷回本（已完成卷的粗粒度记忆，可重建、按指纹判过期）
    chapters/.backups/    # 大幅删改前的自动备份
    .index/chapters.db    # 全文检索索引（可重建缓存，不进备份；可随时删）
    .index/cache-stats.json # 模型调用 usage 与前缀缓存命中统计（可重建观测缓存，不进备份）
    .index/l0-report.json # 各章最近一次 L0 预检结果（可重建，体检面板消费）
    .index/lore-activated.json # 各章最近一次生成的世界书/范文激活留痕（可重建观测缓存，不进备份）
```

## Agent 架构（对话工具层）

批注抽屉里的编辑不是单轮问答，而是一个小型 ReAct 循环：模型可自主调用工具查书，查完再答。

| 工具 | 权限级 | 作用 |
| --- | --- | --- |
| `search_chapters` | execute | 全书正文检索（与前文搜索框同一实现） |
| `read_character_card` | execute | 读完整人物卡（含按章状态时间线） |
| `read_foreshadow_list` | execute | 读伏笔登记表 |
| `read_timeline` | execute | 读世界事件时间线（可按人物/势力、截止章过滤） |
| `read_lorebook` | execute | 读世界书条目（可按关键词过滤、按某章生效范围筛选，含常驻/契约/停用/优先级） |
| `read_chapter` | execute | 读任意章原文（截断） |
| `register_foreshadow` | execute | 登记新伏笔（UI 可见、可撤销） |
| `propose_chapter_content` | **propose** | 整章修订 → 提案卡，作者采纳才落盘 |
| `propose_summary` | **propose** | 摘要重写 → 提案卡，作者采纳才写记忆 |

设计约束：**分级权限**——只读与低风险可撤销写直接执行；不可逆的正文/摘要修改永远走提案（"AI 提案、作者确认"原则）。循环预算 `MAX_STEPS=5`，末轮物理禁工具强制收敛；工具参数全部服务端校验（章 id 必须存在、字段白名单、结果 4000 字截断防上下文爆炸）；平台不支持 `tools` 参数时自动降级为普通对话；演示模式忽略工具单轮回答。UI 侧：回答上方显示逐步工具轨迹，提案内嵌采纳/放弃卡，长任务可随时停止（AbortSignal 掐断整条链）。

## 目录结构

```
server/   Express 后端：文件存储层、模型接入层、agent 编排、SSE 流式路由
  src/ai/prompts/   ★ 所有提示词模板都在这里，想调教文风直接改文件
  src/ai/memory.ts  上下文组装（前情摘要预算、人物卡挑选）
web/      React + Vite 前端：手写 CSS 设计系统；仅弹窗使用 Base UI 无头组件（不带任何样式）
shared/   前后端共享类型（含世界书/范文的激活引擎纯函数与单测）
desktop/  可选的 Tauri 桌面壳：scripts/build-assets.mjs 组装资源；src-tauri/ 为 Rust 外壳
```
